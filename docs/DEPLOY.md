# Публикация и релизы

Сайт статический, поэтому годится любой способ отдачи файлов: GitHub Pages,
обычный хостинг, папка на сервере за nginx.

## GitHub Pages

В репозитории лежит `.github/workflows/pages.yml`. Он собирает `dist/` и
публикует его при каждом пуше в `main`.

Что нужно сделать один раз: **Settings → Pages → Build and deployment →
Source: GitHub Actions**. После этого сайт будет доступен по адресу
`https://nicegenn.github.io/VisitkaStudent/`.

Ссылки внутри сайта относительные, поэтому подкаталог в URL им не мешает.

## Релиз по тегу

`.github/workflows/release.yml` срабатывает на теги вида `v*`: собирает
архив и создаёт GitHub Release с ним во вложениях.

```bash
# 1. добавить раздел в CHANGELOG.md
# 2. поставить тег той же версии
git tag -a v1.0.0 -m "Версия 1.0.0"
git push origin v1.0.0
```

Через минуту релиз появится на вкладке Releases, а в нём —
`visitka-student-v1.0.0.zip`.

## Сборка вручную

```bash
./scripts/build.sh
```

Результат: каталог `dist/` (можно скопировать на сервер целиком) и архив
`release/visitka-student-v<версия>.zip`.

Скрипт заодно проверяет внутренние ссылки и наличие ресурсов — битая ссылка
или потерянная картинка видны сразу, до заливки.

## Обычный хостинг

Содержимое `dist/` кладётся в корень сайта. Ничего настраивать не нужно:
ни PHP, ни базы, ни правил переписывания URL. Индексная страница —
`index.html`.

Для nginx достаточно:

```nginx
server {
    listen 80;
    server_name example.ru;
    root /var/www/visitka;
    index index.html;
}
```

## Перед публикацией

- Прогнать `./scripts/build.sh` и посмотреть на список битых ссылок.
- Проверить, что телефоны, адреса и время приёма в шапке и подвале
  актуальны — они продублированы во всех восьми страницах.
- Помнить про `blag-city.jpg`: 757 КБ на фоновое изображение заметно
  замедляют главную на мобильном интернете.
